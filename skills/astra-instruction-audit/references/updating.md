# Applying selected findings

Read this only when an update is authorized, including a follow-up accepting
findings. Keep the original audit's target, selections, and approval boundaries.

Re-read affected files for intervening edits. Reuse unchanged evidence and edit
only the selected issues. If a change invalidates a proposed fix or an approved
diff, revise that proposal; do not overwrite new work. Keep unknown claims as-is
or explicitly qualified rather than replacing them with invented facts.

When moving detail into a reference, leave a conditional link at the point of use.
Keep essential permissions in the entrypoint. Inspect callers before deleting
resources. A SKILL.md-scoped update may adjust its directly relevant resources;
an explicit file-only limit takes precedence.

Update directly affected project-owned mirrors, adapters, and inventory entries
only when their ownership and relationship to the selected source are established
and the user has not excluded them. A request to change this skill's public name
or options must include the corresponding invocation references. Never follow a
symlink outside the authorized scope. Report needed out-of-scope follow-up instead.

Check final content, frontmatter, paths, relative links, retained requirements,
and affected mirror/adapter parity. Run relevant documented instruction/package
checks when authorized and safe; a command's presence alone does not prove safety.
For changed triggers, consider one matching request and one nearby nonmatching
request. For changed boundaries, consider ordinary local work and a consequential
operation. Call these reasoning checks unless exercised in an actual fresh agent
session; static validation does not establish agent behavior.

Reassess changed files after the edits. Carry forward unchanged scores only if
the files and supporting evidence remain unchanged. If auditing this skill itself,
preserve the original rubric for any before/after comparison; disclose scoring
rule changes separately instead of using them to inflate the apparent improvement.
Repair introduced defects and rerun affected failed checks. Do not repeat successful
checks or broaden testing without a new reason. Report any real blocker precisely.
